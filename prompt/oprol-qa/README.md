## Codexでの使い方

対象プロジェクトのworktreeでCodexを開き、Codex版の本文を貼り付けるか、読める場所にあるファイルの絶対パスを指定してください。このdotfilesリポジトリ自体でProject #8の実装を始めるための文書ではありません。

対象Issueの番号／URL、またはプロンプト内の担当レーンを指定してください。順序・待機条件・PR分割は本文に転記済みのため、別ファイルの参照は不要です。担当範囲だけを直列で進めます。依存の解消状況は最新のProject・Issue・mainで確認します。対象未指定なら確認し、自動選択は行いません。

```text
<このファイルの絶対パス>/issue-driven-parallel-impl-codex.mdを読み、従ってください。
対象リポジトリ: <絶対パス>
対象: Issue #<番号> または 本文のレーン<番号>（必須）
本文の許可・禁止事項に従い、実装・検証・マージ・Issue／Project更新まで進めてください。
```

本文にはcommit・push・PR作成・自己レビュー・修正・条件を満たしたマージ・Issue／Project更新の許可を含みます。PR作成後もCodex自身がマージとDone更新まで進めます。計画だけを確認したい場合は、追加指示で「今回は計画の提示まで。編集・push・マージ・Issue／Project更新は行わないでください」と範囲を限定してください。

## Codex版の方針

- Claudeのteammate・モデル名・専用コマンドへの依存を外し、利用可能な機能に合わせる。
- Orca orchestration・サブエージェント・別workerを使わず、自分で直列に進める。ファイル名は既存の参照を保つため維持している。
- 本文に記載した実装順と待機条件に従い、依存の解消状況は最新のProject・Issue・PR・mainで確認する。
- 指定Issueまたは指定レーンだけを対象にし、担当分が完了したら終了する。対象外の前提Issueや後続レーンへ自動で着手しない。
- 進行中は1手順とし、本文の順序・待機条件・PR分割に従う。部分PRでは実装残件を残し、Issue全体の実装・マージが完了したらDoneにする。
- 細かな仕上げや周辺改善は後続Issueで追跡し、主要実装を優先する。主要機能・必須のエラー処理・安全条件は先送りしない。
- PRは本文の分割に従い、分割指定がなければ原則1件のIssueをDoneにできる単位で作り、必要な検証と自己レビューをそのタイミングに集約する。実装中は必要な確認に絞り、検証の重複や待ち時間を減らす。
- 実装完了・必須検証とレビュー完了・PRマージを確認した実装IssueはCloseし、ProjectをDoneにする。後続の動作確認・QA・受け入れは別Issueへ引き継ぎ、実装IssueをOpenに残す理由にしない。
- 検索は実装判断に必要な範囲で終え、既存テストの対象ファイル・ケースを絞って実行する。新規テストは既存で検出できない重要な回帰・AC・安全条件に限り、不要な追加や全体試験・再実行を避ける。
- Codex自身がPRをレビュー・修正し、条件を満たしたらユーザーの追加承認なしでマージする。自己レビューを明記し、GitHubで必須の第三者承認・保護ルールは守る。

これらは運用方針であり、実際のtoken削減量や実装品質は未計測です。実行環境によって使えるツール・権限は異なります。

参考: [OpenAI公式のプロンプト・スキル見直しガイド](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。対象・制約・完了条件を明示し、不要なコンテキストを減らす方針を参考にしています。
